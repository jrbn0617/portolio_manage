## 3. 비공개 처리 대응표 (알고리즘 #1)

| 유동시총가중 | 유동주식 기준 규모 연동 비중배분 |
| 섹터당 최대 2종목 | 동일 업종 편입 종목수 제한 |
| −10% 손절, 익일 시가 체결 | 사전 정의된 하락 폭 도달 시 익영업일 청산 |
| 200일 이동평균 레짐필터 | 시장의 중장기 추세 이탈 여부 판단 |

| 비중 1% 미만 제외 후 재분배 | 비중이 미미한 종목은 편입하지 않고 잔여 종목에 재배분 |

| 선등록(pre-registration) | 검증 기준을 데이터 확인 전에 문서로 확정 |
| Newey-West / Fama-MacBeth | 통계적 유의성 보정 / 기존 요인 대비 독립성 확인 |

## 5. 성과 수치를 안 쓰고 설득하는 법 (R5 대응)

성과를 못 쓰면 특장점 서술이 빈약해지기 쉽다. 세 가지로 대체한다.

1. **절차를 쓴다** — "무엇을 얼마나 벌었나" 대신 "무엇을 어떻게 검증하고 무엇을 버렸나".
   과최적화 방지 체계(methodology §1)가 통째로 여기 해당하며, 이게 가장 강한 재료다.
2. **판정 기준을 쓴다** — "복수 종목군에서 같은 방향이 아니면 채택하지 않는다"는
   숫자 없이도 규율을 보여준다.
3. **한계를 먼저 밝힌다** — 슬리피지 미반영, 표본 외 검증 미실시 같은 항목을 3장 위험과
   추가필요자료에 적는다. 감점 요인이 아니라 신뢰도 근거로 읽힌다.

## 6. 제출용 한정과 알고리즘 자체를 섞지 말 것

**제출용 설명서에서 유니버스를 하나로 좁히는 것은 문서상의 한정이지 알고리즘의 변경이
아니다.** 알고리즘 #1은 코스피 전체로 제출하지만, `docs/algorithms/algorithm1-overview.md`의
"4개 종목군 병행" 정의는 그대로 둔다. 내부 문서를 제출본에 맞춰 고치면 알고리즘이 실제보다
좁아지고, 나중에 다른 종목군으로 제안할 때 근거가 사라진다.

대신 설명서 쪽에서 두 가지를 한다.

1. **제약조건 블록**에 "제출 대상을 한정한 것이며 알고리즘 자체는 복수 종목군에 동일 설정으로
   적용 가능하다"를 명시한다
2. 1-(3)의 복수 종목군 검증 문단에 **"종목군에 따라 설정값을 달리하지 않는다"**를 덧붙인다 —
   이러면 "왜 다른 종목군 얘기가 나오나"라는 질문이 막히는 동시에 과최적화 방지 근거가 된다

## 7. 규정·서식상의 제약은 "알고리즘대로 하면 자동으로 지켜진다"로 쓸 수 있는지 먼저 본다

제출 서식의 한도·예외 조항을 그대로 옮겨 적기 전에, **우리 알고리즘의 자체 제약이 더 빡빡한지**
확인한다. 더 빡빡하면 예외 조항을 인용할 필요 자체가 없어지고 서술이 짧아진다.

실제 사례 — 서식의 동일종목 한도에는 "시가총액이 시장 전체의 10%를 초과하면 예외"가 붙어
있는데, 알고리즘은 시가총액과 무관하게 25% 상한을 일괄 적용한다. 예외를 설명하는 대신
**"예외에 의존하지 않고 전 종목에 일괄 적용한다"**로 쓰는 편이 짧고 강하다.

## 8. 알고리즘 #2·#3에 쓸 때 주의할 점

- **#2는 유니버스가 코스피200+코스닥150 합집합**이라 2-(1)·2-(2)가 통째로 달라진다.
  #1 문서를 복사한 뒤 유니버스 문단을 안 고치는 실수가 나오기 쉽다.
- **#2는 레짐필터가 기각됐다.** #1의 `[시장국면별 대응력]` 문단을 그대로 옮기면 거짓이 된다.
  methodology §1.5(오버레이 이식 시 재검증)를 확인하고 그 알고리즘에 실제로 들어간 장치만 적는다.
- **#2는 회전율이 더 높다.** 슬리피지·거래비용 서술의 강도를 그에 맞게 조정한다.
- 공통 재료(methodology §1)는 두 문서에서 같은 문장을 써도 된다 — 실제로 같은 체계다.
