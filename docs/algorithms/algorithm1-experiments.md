## 기록 방식

각 실험 완료 시 이 표의 "상태"를 완료로 바꾸고 "결과 요약"에 베이스라인 대비 변동(연변동성/MDD/샤프)을
1줄로 남긴다. 상세 수치·엑셀 파일은 각 실험 브랜치의 커밋에 포함.

| | 격월 | 35.5% | 24.9% | -28.6% | 1.38 | 330% | -0.99%p |
| | 분기 | 23.3% | 22.9% | -29.0% | 1.06 | 247% | -0.74%p |
| 코스닥전체 | 월 | 21.6% | 26.7% | -33.6% | **0.88** | 472% | -1.42%p |
| | 격월 | 9.8% | 25.6% | -29.6% | 0.50 | 302% | -0.90%p |
| | 분기 | 9.6% | 22.0% | -32.0% | 0.54 | 257% | -0.77%p |

**기각 사유**

1. **비용 절감으로 상쇄가 안 된다.** 코스닥150은 샤프가 0.99→0.58(-0.41), CAGR은 12.5%p
   빠지는데 왕복 0.3% 기준 절감은 연 0.43%p뿐이다. **20배 이상 차이**라 왕복 1.0%를
   가정해도 못 메운다.
2. **회전율이 기대만큼 안 줄어든다.** 리밸런싱 횟수가 3분의 1이 되면 회전율도 3분의 1이
   될 거라 봤으나, 회당 회전율이 34%→55%로 늘어 **연환산은 절반밖에 안 줄었다**(412%→220%).
   3개월 사이에 종목이 더 많이 바뀌기 때문이다.
3. **코스피200 격월만 개선**(샤프 1.26→1.29, MDD -32.0%→-24.2%)이고 나머지 3개는
   -0.11~-0.41로 악화 — 실험 3(변동성조정 모멘텀)·13(섹터캡 필드)과 같은 "단일 유니버스
   한정, 범용성 없음" 사례.

**부수적 결론**: "12개월짜리 느린 신호는 매달 안 재도 된다"는 직관이 틀렸다. **신호 자체는
느려도 상위 20종목 경계에서의 순위 교체가 성과를 만든다.** 알고리즘 #2(6개월 모멘텀)에서
월간이 분기를 압도한 것과 같은 결론이 12개월에서도 나왔다.

**교란 요인(미분리)**: 주기를 늘리면 손절 창(직전 리밸런싱 종가 대비 -10%)이 3개월로
길어지고 레짐필터 판정도 연 4회로 둔해진다. 격월에서 이미 결론이 명확해 분리하지 않았다.

`BacktestConfig.rebalance_months`(기본 1)는 `experiment/16-rebalance-frequency` 브랜치에만
있고 main에 병합하지 않았다.

### 실험 17: EBITDA PEG 스크리닝 강도

**동기**: 스크리닝 **하류**(랭킹·가중·캡·리스크 오버레이)는 전부 튜닝했으면서 **스크리닝
자체**(`screen_top_pct=0.5`)는 초기값 그대로였다. 실험 1(통합스코어)·2(PEG>0 완화)는 PEG를
*어떻게* 쓸지만 봤지 *얼마나* 쓸지는 안 봤다. 답할 질문은 **"PEG 스크리닝이 실제로 돈을
벌어주는가, 아니면 유니버스를 좁히기만 하는가"**다.

**대조군 설계 — `--screen-top-pct 1.0`은 대조군이 못 된다.** 스크리닝은 두 단계다:
(1) 하드 필터 = EBITDA(Fwd.12M) ≤ 0, 성장률 ≤ 0, 컨센서스 없음 → 무조건 탈락,
(2) 상대 필터 = 살아남은 종목 중 섹터별 PEG 하위 `top_pct`. `top_pct=1.0`은 (2)만 끄고
(1)은 그대로다. 실측으로 코스피200 200종목 중 100%로 풀어도 111~145개만 통과했다.
그래서 `screen_fn` 자체를 끄는 `--no-screen` 플래그를 추가했다(이 플래그만 main 병합).

**통과 종목수** (섹터별 컷 적용 후)

| 유니버스 | 전체 | 30% | 50% | 70% | 100% |
|---|---|---|---|---|---|
| 코스피200 | 200 | 34~42 | 54~69 | 77~100 | 111~145 |
| 코스피전체 | 910~958 | 68~107 | 115~173 | 157~250 | 224~355 |
| 코스닥150 | 150 | 21~35 | 39~58 | 55~80 | 82~113 |

**결과** (샤프 / CAGR)

| 유니버스 | 30% | **50%(현행)** | 70% | 100% | 스크리닝 없음 |
|---|---|---|---|---|---|
| 코스닥150 | **1.14** / 29.9% | 0.99 / 24.5% | 0.86 / 21.4% | 0.66 / 15.4% | 0.43 / 8.2% |
| 코스피200 | **1.38** / 35.5% | 1.26 / 30.4% | 0.97 / 21.3% | 1.00 / 22.4% | 1.13 / 27.3% |
| 코스피전체 | 1.32 / 33.8% | **1.49** / 38.1% | 1.31 / 33.5% | 1.03 / 25.3% | 실행실패 |
| 코스닥전체 | 0.59 / 12.4% | **0.88** / 21.6% | 0.69 / 16.0% | 0.52 / 11.0% | 실행실패 |

**결론 1 — 스크리닝은 기여한다.** 100%로 풀면 4개 유니버스 **전부** 샤프가 떨어진다
(0.99→0.66, 1.26→1.00, 1.49→1.03, 0.88→0.52). 예외가 없어 실험 14의 종목캡처럼 구조다.
**"그냥 모멘텀 전략 아니냐"는 의심은 기각된다.** 또한 100%가 곧 "성장률>0만 거르는 설정"인데
4개 다 나쁘므로, **PEG가 싼 쪽을 고르는 행위 자체가 값어치를 한다** — 더 단순한 규칙으로
대체할 수 없다.

**결론 2 — 30% 조이기는 채택 불가.** 코스닥150(+0.15)·코스피200(+0.12)은 크게 개선되나
코스피전체(-0.17)·코스닥전체(-0.29)는 크게 악화되고, **MDD는 4개 전부 나빠진다**
(코스닥전체 -33.6%→-48.5%). 2:2로 갈리고 진폭도 커서 단일설정 원칙상 기각.

**결론 3 — 50% 유지.** 확정안 변경 없음.

**미완**: "스크리닝 없음" 대조군은 코스피전체·코스닥전체에서 실행 실패했다. 스크리닝을
끄면 유니버스가 910~958종목으로 넓어져 미등록 시계열단절 종목이 편입되기 때문이다
(096300, 426550, 427950 — 셋 다 `instruments.name`이 티커 그대로인 마스터 결측 종목군).
결론에는 영향이 없다(스크리닝 기여는 100% 설정 4개 전부에서 확인됨).

**엔진 교체 영향 확인**: 이 실험 도중 다른 세션이 백테스트 엔진에 거래정지 종목 필터
(`find_halted_instruments`)를 추가했다. 거래정지 종목이 0% 모멘텀으로 후보에 남아 있었으므로
**스크리닝을 풀수록 대조군이 오염됐을 것**으로 예상하고 전량 재실행했으나, 차이는 최대
±0.02였다. 0% 모멘텀은 상승장에서 상위 20위에 못 들어 하락 구간에서만 문제가 되는데 그
구간이 짧았기 때문이다. (엔진 수정 자체는 필요하다 — 실제로 살 수 없는 종목을 담는 것은
백테스트 수치와 무관하게 막아야 한다.)
